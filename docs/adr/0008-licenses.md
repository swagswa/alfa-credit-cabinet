# 8. Политика лицензий

Дата: 2026-10-20

## Статус

Принято

## Контекст

Условия кейса: никаких платных подписок, API и закрытых лицензий в сдаваемой версии, LLM только с открытыми весами. Несколько популярных проектов за последние годы ушли с open source лицензий, и по старой памяти их легко затащить.

## Решение

Берём только бесплатные компоненты под лицензиями, одобренными OSI (MIT, BSD, Apache-2.0, MPL-2.0, PostgreSQL), для шрифтов SIL OFL. MPL-2.0 (River) используем без модификации исходников. GPL допустима только у инструментов разработки, которые не попадают в образ (golangci-lint).

Не берём:

| Что | Почему | Вместо |
|---|---|---|
| Camunda 8 | Camunda License 1.0 с версии 8.6 | своя машина состояний (ADR 0004) |
| HashiCorp Vault | BSL | `.env`, если понадобится, OpenBao (MPL-2.0) |
| Liquibase 5 | FSL | goose (MIT) |
| Redpanda | BSL | Kafka 4 в KRaft, если понадобится |
| River Pro | платный | River (MPL-2.0) |
| Qwen2.5-3B, Qwen2.5-72B | собственные лицензии Qwen, не Apache | Qwen3 (Apache-2.0) |
| Фирменные шрифты Альфы | коммерческие | Inter (OFL) |

Каждая новая зависимость проверяется при добавлении и в том же PR вносится в THIRD_PARTY_NOTICES с версией и лицензией. Там же модели и список смоделированных интеграций (ЕГРЮЛ/ЕГРИП, БКИ, ФНС, подписание, выдача).

## Последствия

- Прототип можно сдавать и разворачивать без юридических вопросов.
- Лицензию модели проверяем по карточке конкретного размера: у одного семейства они бывают разные.
