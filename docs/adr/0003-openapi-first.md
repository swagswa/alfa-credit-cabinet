# 3. Контракт API первым

Дата: 2026-10-20

## Статус

Принято

## Контекст

Фронт и бэк пишутся параллельно разными людьми. Кейс требует OpenAPI и описание API в комплекте сдачи. Если выводить спеку из кода или вести спеку и типы отдельно, они расходятся уже на второй день.

## Решение

Единственный источник контракта: `api/openapi.yaml`.

- Сервер, типы и валидация запросов генерируются oapi-codegen в режиме strict server под echo (`internal/httpapi/api.gen.go`, ADR 0013). Руками пишем только тела методов `StrictServerInterface`.
- Валидация входа по той же спеке через `oapi-codegen/echo-middleware` (kin-openapi внутри). Повторно в хендлерах её не делаем.
- Фронт генерирует типы через openapi-typescript (`web/src/api/schema.d.ts`) и ходит в API через openapi-fetch.
- В спеке описана схема входа через cookie (`securitySchemes`). Права ролей на операции лежат в политике casbin (ADR 0011), а не в спеке.
- Swagger UI в compose отдаёт тот же файл.
- Контракт меняется только через PR. Сгенерированный код коммитится отдельным коммитом, CI проверяет, что он совпадает со спекой.

## Последствия

- Фронт стартует в первый день на моках ответов, не дожидаясь бэка.
- Расхождение контракта ловит компилятор с обеих сторон.
- Ограничения полей (паттерн ИНН, диапазоны сумм) живут в одном месте.
- ogen не взяли: генерирует строже, но серверного SSE нет, а на нём живой статус заявки.
- oapi-codegen команда приняла после демо генерации strict server.
