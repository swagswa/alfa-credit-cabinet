# 13. HTTP на echo

Дата: 2026-10-20

## Статус

Принято. Уточняет ADR 0002, 0003 и 0011.

## Контекст

В ADR 0002 HTTP был на `net/http` без фреймворка: роутинг генерирует oapi-codegen, middleware немного. При раскладке каркаса набралось то, что на голом `net/http` пишется руками: recover, request id, CORS для dev-сервера фронта, проверка JWT из cookie, единая обработка ошибок, отдельный маршрут под SSE. Всё это у echo есть готовое и проверенное.

## Решение

- echo v4 (`github.com/labstack/echo/v4` v4.16.0, MIT). v5 (5.4.0) уже вышел, но валидатор запросов `oapi-codegen/echo-middleware` есть только под v4, а v4 поддерживается и выходит параллельно.
- oapi-codegen v2.8.0 генерирует `echo-server` и `strict-server`, плюс `embedded-spec`. Руками пишем тела методов `StrictServerInterface`, как и раньше.
- Валидация входа по спеке: `github.com/oapi-codegen/echo-middleware` v1.1.0 (Apache-2.0), `OapiRequestValidator`. В хендлерах повторно не проверяем.
- Middleware из echo: `Recover`, `RequestID`, `CORS` (только для dev-сервера Vite, в compose фронт и API на одном origin через nginx). JWT из cookie проверяет `github.com/labstack/echo-jwt/v4` v4.4.0 (MIT, `TokenLookup: "cookie:..."`). Своя middleware одна: casbin `Enforce(role, path, method)`, ADR 0011.
- Ошибки: одна функция маппинга доменных ошибок в `application/problem+json` в `e.HTTPErrorHandler`.
- SSE живого статуса это обычный хендлер echo вне strict server: `http.ResponseController`, события из `LISTEN/NOTIFY`. В спеке операция описана и исключена из генерации через `exclude-operation-ids`.
- `http.Server` с `ReadHeaderTimeout` и graceful shutdown остаётся своим, echo это его `Handler`.

## Последствия

- Минус несколько своих middleware и ручной разбор cookie.
- Ещё одна зависимость, MIT, вносим в THIRD_PARTY_NOTICES.
- Переход на echo v5 это смена генератора на `echo5-server` и валидатора, когда тот появится под v5. Хендлеры strict server при этом не меняются.
