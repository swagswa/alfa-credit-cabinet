# 4. Машина состояний заявки: своя таблица переходов и River

> Заменено [ADR 0012](0012-temporal.md): процесс заявки ведёт Temporal.

Дата: 2026-10-20

## Статус

Заменено ADR 0012

## Контекст

Заявка проходит десяток статусов: черновик, подана, проверка, запрос уточнений, скоринг, решение (одобрено, контрпредложение, ручное рассмотрение, отказ), подписание, выдача. Автоматических шагов три-четыре, остальное действия людей. Статус должен меняться последовательно, с аудитом, и обе стороны должны видеть одно и то же.

Рассматривали:

- Temporal: 1-4 дополнительных контейнера, до 1.2 ГБ RAM, 300-500 строк обвязки, требования детерминизма workflow и второй источник правды о статусе. Решает задачу долгих процессов с таймерами, которой у нас нет.
- BPMN-движок. Camunda 8 с версии 8.6 под Camunda License 1.0, в проде только по лицензии. Operaton (форк Camunda 7, Apache-2.0) это ещё одна JVM на 0.5-1 ГБ, а Go-клиент `camunda-client-go` заброшен с 2023 года.

## Решение

Переходы описываем таблицей в `internal/credit/transitions.go`: из какого статуса, в какой, какой роли разрешено. Статус меняется только функцией `credit.Transition(ctx, tx, appID, to, actor, reason)`, в одной транзакции:

- `SELECT ... FOR UPDATE` и проверка перехода по таблице;
- запись в журнал аудита, `version+1`;
- `pg_notify` для живого статуса в интерфейсе;
- постановка следующего шага в River через `InsertTx` (ADR 0005).

`AllowedNext(status, role)` отдаётся фронту, кнопки действий строятся по нему. Диаграмма `docs/state-diagram.md` сверяется golden-тестом: тест рендерит Mermaid из таблицы и сравнивает с файлом, расхождение валит CI. Ожидания разрешённых и запрещённых переходов в тестах ядра пишутся руками.

## Последствия

- Один источник правды о статусе: таблица `applications`. Новых контейнеров ноль.
- Диаграмма в комплекте сдачи совпадает с кодом по построению.
- Таймеров, компенсаций и визуального редактора процесса нет. Если появятся долгие процессы с десятками участников, шаги уже изолированы как джобы River и переносятся в activities Temporal или задачи BPMN без переписывания логики.
