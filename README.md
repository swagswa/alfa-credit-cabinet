# Кредитный кабинет предпринимателя

Прототип для кейса Альфа-Банка на Альфа-Хак 2026: клиент подбирает кредит и ведёт заявку, банк в своём кабинете проводит её через проверки, скоринг и решение.

Сейчас в репозитории каркас: процессы, инфраструктура, контракт API и схема БД. Бизнес-логики ещё нет, все операции кроме `/api/health` отвечают 501.

## Запуск

Нужен Docker с compose v2. Больше ничего ставить не надо.

```sh
docker compose up -d --build --wait
```

| Что | Адрес |
|---|---|
| Фронт | http://localhost:8000 |
| API | http://localhost:8080/api, проверка: `/api/health` |
| Swagger UI | http://localhost:8082 |
| Temporal UI | http://localhost:8233 |
| Моки внешних систем | http://localhost:8081 |

Распознавание документов (Ollama, Qwen3-4B, Tesseract) в отдельном профиле, при первом запуске скачивается модель около 2,5 ГБ:

```sh
AI_ENABLED=true docker compose --profile ai up -d --build --wait
```

Значения по умолчанию лежат в `compose.yaml`, переопределяются через `.env` (образец в `.env.example`). Если порт занят, поменяй его там же.

## Вход

Сессии серверные: при входе `api` заводит сессию в Redis, в cookie `session` уходит подписанный токен с её номером. Выход удаляет сессию, токен сразу перестаёт работать. Попыток входа с одного адреса не больше `LOGIN_ATTEMPTS` за `LOGIN_WINDOW` (по умолчанию 10 в минуту). На стенде по http `COOKIE_SECURE=false`, за https его нужно включить, иначе cookie будет уходить открытым текстом.

## Устройство

Модульный монолит: один репозиторий и один Go-модуль, но четыре процесса.

| Процесс | Что делает |
|---|---|
| `api` | HTTP API и живые события (SSE), стартует процесс заявки в Temporal |
| `worker` | ведёт заявку: проверки во внешних системах, скоринг, решение, выдача |
| `docs-worker` | распознаёт выписки и отчётность, отдельно, потому что тяжёлый и с другим образом |
| `mocks` | симулятор ЕГРЮЛ/ЕГРИП, ФНС, БКИ и внутренних данных банка |

Код разложен по слоям: `internal/domain` (сущности и правила без I/O), `internal/repo` (SQL через sqlc), `internal/usecase` (логика и транзакции), `internal/api` и `internal/worker` (вход снаружи). Переиспользуемая инфраструктура в `pkg/`. Контракт API в `api/openapi.yaml`, статусы заявки в `docs/state-diagram.md`, модель данных в `docs/data-model.md`.

Почему продукт устроен так, а не иначе: боли клиентов и банка, источники и границы MVP в [docs/research.md](docs/research.md).

## Разработка

Go 1.27, Node 24, Docker.

```sh
make generate   # сервер из api/openapi.yaml, код запросов из internal/db/queries
make lint
make test       # интеграционные тесты поднимают Postgres через testcontainers
make check      # всё, что проверяет CI
```

Фронт отдельно: `cd web && npm ci && npm run dev`, dev-сервер проксирует `/api` на `localhost:8080`.

## Синтетические документы

Для распознавания и кнопки «Взять пример выписки» лежит готовый набор в `testdata/documents`, пересобирается `make docgen`, повторный запуск даёт те же байты. Там выписки трёх форматов: a и b это текстовые PDF двух выдуманных банков с разными колонками и подписями, c это «скан» PNG с поворотом и шумом (один экземпляр завёрнут в PDF без текстового слоя). Плюс отчётность формата a и ловушка `0000300011_statement_a_trap.pdf`, где приход завышен в 1,5 раза. Рядом с каждым файлом `.truth.json` с полями, которые должно достать распознавание.

Компании: четыре демо и две из генератора (`0012345673`, `001234567887`). Один документ по любому ИНН:

```sh
go run ./cmd/docgen -inn 0000300011 -kind statement -format b -out /tmp/docs
```

Цифры считает `internal/mocks/synth`, тот же пакет будет кормить мок ФНС. Допущение: выручка за прошлый год в ФНС равна поступлениям по выписке за 12 месяцев (октябрь 2025 - сентябрь 2026). Иначе при росте выручки честная выписка расходилась бы с налоговой больше чем на 20% и падала в ручную проверку вместе с ловушкой.

## Распознавание документов

Работает только в профиле `ai`: `docs-worker` на очереди `docs` берёт текстовый слой PDF, сканы прогоняет через Tesseract (`-l rus+eng --psm 6`), поля по JSON-схеме достаёт `qwen3:4b-instruct-2507-q4_K_M` в Ollama, дальше проверки в Go: ИНН совпадает с заявкой, период до 13 месяцев и не в будущем, остаток на начало плюс приход минус расход равен остатку на конец, помесячный приход сходится с итогом. Не сошлось, документ `failed` и клиент вводит итоги руками. Без профиля документ `skipped`.

Настройки `docs-worker`: `TESSERACT_PATH` (по умолчанию `tesseract` из PATH), `TESSDATA_PREFIX`, если языки не в стандартном каталоге, `OLLAMA_URL`, `OLLAMA_MODEL`, `OCR_TIMEOUT` на страницу, `OLLAMA_TIMEOUT`.

Точность меряет `make eval-docs` на `testdata/documents`, итог с моделью, digest и временем в `docs/ai-eval.md`. Локально нужны tesseract с языками rus и eng и Ollama с моделью; ollama из compose порт наружу не публикует, так что для прогона подними свою или задай `OLLAMA_URL`.

Допущения: суммы в документе в рублях, отчётность в тысячах рублей пока не поддерживаем; не больше 5 страниц; модель видит первые 12 000 символов текста.
